# 共享聊天服务与 30 天保留期

## 登录与跨端同步

标准 APK 的公开 HTTPS 入口来自 `deploy/chat-public.json`。账号、密码和管理令牌由各实例管理。安卓 WebView 保存安全会话 Cookie，服务器仅保存随机令牌的摘要；退出会撤销当前设备的会话。勾选记住状态时，普通账号的有效窗口为 30 天，最长续至登录后 90 天；管理员为 1 天和 7 天。会话过期后用原账号重新登录。

每条消息在数据库提交后返回服务端 ID。私聊、AI 私聊和群聊使用同一数据模型。实时 SSE 推送当前成员可读取的变化，重连按消息修订游标补齐。会话历史用消息 ID 向前分页，旧客户端的 `after` 分页入口仍可用。已读按账号和消息保存，通知在已读同步后清除。会话 ID 与消息 ID 均从服务器取得。

`GET /api/chat/threads/:id/sync?cursor=…` 拉取变更。首次打开会话可从历史接口取得 `syncCursor`。`GET /api/chat/threads/:id/search?q=…` 按当前成员权限搜索本会话。查看、分页、搜索、同步、已读和附件使用同一个服务端时间边界。

## 服务端保留

服务器保留最近30天聊天记录。到达创建时间后的 30×24 小时即停止返回，查看、下载和更新不改变期限。服务端启动后执行一次批量清理，之后每 15 分钟运行。必要时可对既有聊天库重复运行 `pnpm chat:prune`。迁移 `008-chat-retention-and-sync.sql` 保存消息修订、附件关联和最少的过期发送摘要。重复提交一个已到期的发送编号会收到 `410 message_expired`。

清理只回收无其他有效引用的私有聊天附件。已发布网站资源、头像、角色卡和独立 AI 记忆按各自策略保存。隔离测试会检查这些业务引用。AstrBot 连接器 0.3.1 按消息期限清理回复缓存，将以前重复写入的聊天历史从其管理的会话中移除，保留会话映射和人格。聊天后端只构建保留期内的历史上下文，独立记忆仍受原授权约束。

应用保存本机未发送草稿与会话位置。用户通过系统文件窗口下载或导出的文件由用户管理。

## 验证与部署

隔离测试服务由 `scripts/android-fixture.mjs` 启动，Windows 开发端可通过 `TSUKIAKARI_CHAT_SERVER_URL` 指向同一演示入口。标准桌面共享模式使用 `pnpm package:desktop --shared-chat`，新版桌面也可通过 `--shared-chat` 启动。旧本地库可通过 `--local` 继续打开。

1. 从已有实例核对哪个聊天库持有正式账号、好友、群聊、消息与媒体。先制作一致性 SQLite 快照，在隔离路径试跑迁移和恢复。保留旧客户端数据目录与备份。分散在各设备的独立本地库需要先梳理来源；任意一个本地库都不能自动覆盖共享库。
2. 将确认后的聊天库配置为独立 `DATABASE_PATH`。部署 `deploy/moonlit-chat.service` 和服务端配置 `deploy/chat.env.example`，其中网站入口、会话与 AstrBot 凭证由服务器运维保管。网站沿用独立数据库。迁移完成后，本机 `/api/chat/session` 应在匿名访问时返回 `401 login_required`。
3. 通过现有站点代理配置加入聊天路由，先校验 Nginx，再重载。生产 HTTPS 验证同一账号的实时事件、附件、会话和通知。保留需同步的两端数据都来自此聊天库。
4. 启用 `moonlit-chat-backup.timer`。默认每天生成私有聊天数据库快照，验证成功后按 3 份和 3 天两个上限轮换。失败时保留最近可用的副本。备份副本清理已到期消息并移除旧会话，再校验媒体。网站和 Bot 备份由各服务单独管理，跨服务归档也采用受控的保存期限。

恢复使用新 `DATABASE_PATH` 和 `pnpm db:restore <备份副本>`。脚本迁移并清理到期数据、撤销快照中的登录会话、检查完整性，再落到新的目标路径。检查后再切换服务指向。旧路径和备份原件保留。手工恢复或回退到旧快照后同样先走清理和验证流程，再开放流量。
