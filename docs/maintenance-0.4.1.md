# 月明かり 0.4.1 版本说明

2026-11-20。继续使用 Electron 45.3.1、Node.js 24.22.3 和两个独立的 SQLite 后端。本次没有数据库结构变更，原账号、会话、站点内容、媒体和桌面配置可继续使用。

## 排查与修复

| 问题与复现 | 影响 | 0.4.1 的行为 |
| --- | --- | --- |
| 实时消息连接返回 HTTP 503，随后恢复服务 | 旧版守在断开的连接，遗漏消息要刷新页面才能看到 | 断线时显示状态和重连入口。后台退避重试，恢复后补齐会话消息 |
| 打开一段响应较慢的会话，返回前先进入设置 | 迟到响应覆盖会话选择，返回聊天时落到错误会话 | 路由中止过期请求，保留原会话和草稿 |
| 加载完旧记录，再让窗口获得焦点 | 已读完的分页入口重新出现，重复改写正文和发送控件 | 保留历史游标，只应用变化的消息，复用侧栏和输入控件 |
| 隐藏窗口，在另一账号发送消息 | 旧版后台仍渲染，并把这批消息误标已读 | 原生隐藏与最小化状态校正渲染器；后台保留连接和未读，恢复窗口时重读最新消息 |
| 正在翻看旧记录时收到新消息，或延迟发送时切换会话 | 已读边界和草稿可能与当前看到的内容不一致 | 读到最新处才清除届时可见的消息；发送绑定原会话，附件和文本随各自草稿保留 |
| 并发重试首条 AI 消息，或第一次选择人格时服务不可用 | 重试可能撞数据库唯一约束，创建与选择分开时可留下空会话 | 重试复用同一消息和回复；新建会话与选择人格一起提交。好友私聊的普通消息留在好友之间 |
| AstrBot 人格版本冲突、授权失效，或写入回读后列表不可用 | 原输入容易被重读覆盖，部分成功看起来像失败，远程 401 会使聊天退出 | 保留待提交草稿，可对照当前服务器版本。确认写入和回读后才标记同步，并单独提示列表状态 |
| 网站后台独立会话过期 | 操作者缺少重连入口 | 网站管理提供独立登录，编辑表单可保留 |
| 构建时上游下载偶发断开 | 同版本重复打包会卡在许可证下载 | 锁定的 Node 版本从仓库读取官方许可证。依赖安装仍按锁文件执行 |

输入区缩减空白，使用统一的焦点边框与清楚的发送、停止和失败状态。翻阅历史时可以使用「回到最新」或「查看新消息」。增加辅助文字对比度，长代码块在消息内部滚动。AI 流式输出更新现有文本节点，助手生成状态不再反复重建发送按钮。

## 验收

- 普通账号登录失败和重试、资料保存、按稳定 ID 找好友、接受好友与群邀请，以及两套管理权限均已检查。
- 真实 Electron 窗口复现断线和重连、迟到的会话请求、发送失败重试、长消息和图片上传。测试覆盖 800×580 原生窗口与 125% 缩放。
- 托盘隐藏、恢复、保留未读、关闭任务栏标记，以及返回最新消息后清理未读均已检查。
- 人格对照、AstrBot 拒绝授权后的草稿恢复、同步回读、网站后台独立重连均已检查。新版界面写入真实 AstrBot 后版本读回一致，也完成了大肥鱼的真实流式对话。真实连接器另外完成 JSON 和 PNG 角色卡写入回读、独立群会话及重试验证。
- 用 0.4.0 资料副本直接打开 0.4.1，保留原登录、账号、会话和媒体。工作区外打包程序、单文件免安装启动、关闭退出、重启后的数据读取均通过。
- 41 项后端测试和 11 组网站浏览器验收通过。截图取自使用演示数据的真实窗口。真实服务凭据与账号数据保存在本机。

同一台 Windows 电脑上的前后对比。刷新场景为加载 66 条消息，后台场景为隐藏窗口后分批接收 8 条消息。DOM 数字统计子节点变动，CPU 和内存只统计对应渲染进程。

| 隐藏时聊天消息区变动 | 8 | 0 |
| 隐藏时保留未读 | 0 | 8 |

两次滚动采样均未出现超过 34 ms 的帧。CPU 与工作集为单次本机采样，受 Windows 调度及缓存影响。无法用此结果保证其他设备的帧率或系统通知展示。
